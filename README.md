# NexusMem / LinearRAG Memory API

This repository exposes LinearRAG as an Agent Memory Challenge style memory
service. The service provides `/add` for synchronous memory ingestion and
`/search` for ranked evidence retrieval. It does not generate final natural
language answers in the API layer.

## API Entry Points

When the service is running on the server, the usual local API base URL is:

```bash
http://127.0.0.1:8000
```

The current deployment is also exposed through a Cloudflare Tunnel. The public
URL is generated by `cloudflared`; at the time this document was written the
active URL was:

```bash
https://arkansas-expects-universities-silly.trycloudflare.com
```

The API routes are:

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/health` | No | Check service health and whether auth is required. |
| `POST` | `/add` | Yes if token configured | Persist and index new conversation messages. |
| `POST` | `/search` | Yes if token configured | Retrieve ranked memory evidence for a query. |

`/health` returns:

```json
{
  "success": true,
  "service": "linearrag-memory-api",
  "auth_required": true
}
```

## Authentication

Set one of the following environment variables before starting the API:

```bash
export LINEARRAG_API_TOKEN="<your-api-token>"
# or, for backward compatibility:
export MEMORY_API_KEY="<your-api-token>"
```

If neither variable is set, `/add` and `/search` accept unauthenticated
requests. For the competition platform, keep authentication enabled.

Accepted request headers:

```text
Authorization: Token <your-api-token>
Authorization: Bearer <your-api-token>
X-Api-Key: <your-api-token>
```

## Request And Response Format

### `POST /add`

Request body:

```json
{
  "request_id": "unique-add-request-id",
  "user_id": "user-or-conversation-id",
  "session_id": "session-id",
  "messages": [
    {
      "role": "user",
      "speaker": "Alice",
      "timestamp": 1704067200000,
      "content": "Alice currently likes jasmine tea and works at SmokeTest Labs."
    }
  ]
}
```

Fields:

- `request_id`: idempotency key. Reusing the same value will not re-index the same request.
- `user_id`: memory namespace. Different `user_id` values are isolated.
- `session_id`: source session id.
- `messages`: list of messages to index.
- `role`: message role, usually `user` or `assistant`.
- `speaker`: optional speaker name used by the memory rules.
- `timestamp`: optional numeric or string timestamp.
- `content`: message text.

Successful response:

```json
{
  "success": true,
  "request_id": "unique-add-request-id",
  "user_id": "user-or-conversation-id",
  "session_id": "session-id"
}
```

### `POST /search`

Request body:

```json
{
  "user_id": "user-or-conversation-id",
  "query": "What drink does Alice currently like?",
  "top_k": 10,
  "options": ["jasmine tea", "coffee", "orange juice"]
}
```

Fields:

- `user_id`: memory namespace to search.
- `query`: search question.
- `top_k`: number of evidence items to return, capped at `100`.
- `options`: optional answer choices; used as an extra reranking signal.

Successful response:

```json
{
  "data": [
    {
      "id": "passage-or-memory-id",
      "content": "Alice: Alice currently likes jasmine tea and works at SmokeTest Labs.",
      "score": 0.1234
    }
  ]
}
```

If the user namespace does not exist or has no indexed passages, the response is:

```json
{"data": []}
```

## Configuration

Core runtime configuration:

| Variable | Default | Meaning |
| --- | --- | --- |
| `LINEARRAG_API_TOKEN` | empty | Primary API token for `/add` and `/search`. |
| `MEMORY_API_KEY` | empty | Backward-compatible token alias. |
| `LINEARRAG_STORAGE_DIR` | `import_api` | Root directory for per-user memory state. |
| `LINEARRAG_EMBEDDING_MODEL` | `model/all-mpnet-base-v2` | SentenceTransformer model path/name. |
| `LINEARRAG_DEVICE` | auto | `cuda` if available, otherwise `cpu`; can be forced. |
| `LINEARRAG_SPACY_MODEL` | `en_core_web_sm` | Primary spaCy model. |
| `LINEARRAG_SPACY_FALLBACK_MODEL` | `en_core_web_trf` | Fallback spaCy model. |
| `LINEARRAG_BATCH_SIZE` | `64` | Embedding batch size. |
| `LINEARRAG_MAX_WORKERS` | `4` | Worker count for indexing components. |
| `LINEARRAG_MAX_CHUNK_CHARS` | `3500` | Max chunk length before indexing. |
| `LINEARRAG_MAX_CACHED_USERS` | `4` | Number of user RAG objects kept in memory. |
| `LINEARRAG_DEFAULT_TOP_K` | `100` | Default internal retrieval size. |
| `LINEARRAG_MIN_SCORE` | empty | Optional score threshold for search results. |
| `LINEARRAG_GRAPHML_WRITE_INTERVAL` | `5` | Write GraphML every N add batches; `0` disables GraphML writes. |

Memory and retrieval feature switches:

| Variable | Default | Meaning |
| --- | --- | --- |
| `LINEARRAG_ENABLE_MEMORY_LAYER` | `true` | Enable rule/spaCy memory extraction sidecars. |
| `LINEARRAG_ENABLE_STATUS_RERANK` | `true` | Use active/expired/conflicting memory status during search rerank. |
| `LINEARRAG_ENABLE_EVIDENCE_RERANK` | `true` | Apply evidence, speaker, answer-type, and time reranking signals. |
| `LINEARRAG_ENABLE_MEMORY_SIDECAR_RETRIEVAL` | `true` | Let consolidated memories boost their raw evidence passages. |
| `LINEARRAG_MEMORY_SIDECAR_TOP_K` | `16` | Max sidecar memory matches. |
| `LINEARRAG_MEMORY_SIDECAR_WEIGHT` | `1.15` | Strength of sidecar boost. |
| `LINEARRAG_MEMORY_SIDECAR_MIN_FIT` | `0.22` | Minimum sidecar fit score. |
| `LINEARRAG_USE_VECTORIZED_RETRIEVAL` | `false` | Use vectorized entity propagation if enabled. |
| `LINEARRAG_ENABLE_ATTRIBUTE_FALLBACK` | `true` | Add keyword fallback for attribute-like questions. |

Structured graph configuration:

| Variable | Default | Meaning |
| --- | --- | --- |
| `LINEARRAG_ENABLE_STRUCTURED_MEMORY_GRAPH` | `true` | Add event/time structured nodes to the LinearRAG graph. |
| `LINEARRAG_STRUCTURED_NODE_TOP_K` | `24` | Number of structured nodes considered as query entries. |
| `LINEARRAG_STRUCTURED_NODE_WEIGHT` | `0.35` | Base structured node activation weight. |
| `LINEARRAG_STRUCTURED_EVENT_WEIGHT` | `1.0` | Event node type multiplier. |
| `LINEARRAG_STRUCTURED_MEMORY_WEIGHT` | `0.9` | Reserved memory node multiplier. |
| `LINEARRAG_STRUCTURED_TIME_WEIGHT` | `0.8` | Time node type multiplier. |
| `LINEARRAG_STRUCTURED_SCORE_THRESHOLD` | `0.2` | Minimum structured node similarity threshold after top ranks. |

Optional LLM-related configuration:

| Variable | Default | Meaning |
| --- | --- | --- |
| `LINEARRAG_ENABLE_LLM_QUERY_INTENT` | `false` | Use an LLM to refine temporal query intent when keys/base URL are configured. |
| `LINEARRAG_QUERY_LLM_MODEL` | `gpt-4o-mini` | Query-intent model name. |
| `LINEARRAG_QUERY_LLM_BASE_URL` | empty | Chat-completions compatible base URL. |
| `LINEARRAG_QUERY_LLM_API_KEY` | empty | API key for query-intent calls. |
| `LINEARRAG_QUERY_LLM_TIMEOUT` | `4` | Query-intent timeout in seconds. |
| `LINEARRAG_ENABLE_LLM_MEMORY_EXTRACTION` | `false` | Use an LLM for add-stage structured memory extraction. Disabled by default. |
| `LINEARRAG_EXTRACT_LLM_MODEL` | query model | Add-stage extraction model name. |
| `LINEARRAG_EXTRACT_LLM_BASE_URL` | query base URL | Add-stage extraction base URL. |
| `LINEARRAG_EXTRACT_LLM_API_KEY` | query key | Add-stage extraction API key. |
| `LINEARRAG_ENABLE_LIGHTWEIGHT_LLM_EXTRACTION` | `false` | Lightweight extraction caps if LLM extraction is enabled. |
| `LINEARRAG_ENABLE_LLM_RERANK` | `true` | Enable optional LLM-style rerank path when configured in code. |

Do not commit real API tokens or keys into this repository.

curl -sS -X POST "$BASE/add" \

  -H "Authorization: Token $TOKEN" \

    "user_id": "smoke:user:1",
    "session_id": "smoke:session:1",
    "messages": [
      {
        "role": "user",
        "speaker": "Alice",
        "timestamp": 1704067200000,

      }

curl -sS -X POST "$BASE/search" \
  -H "Content-Type: application/json" \

  -d '{

Expected behavior:

- `/health` returns HTTP `200`.
- `/add` returns `{"success": true, ...}`.

- Without a valid token, `/add` and `/search` return HTTP `401` when auth is configured.

## Storage Layout

`user_id` is mapped to a SHA-256 namespace:

```text
LINEARRAG_STORAGE_DIR/users/<sha256(user_id)[:32]>/
```

Each user namespace stores its own files, for example:

```text
metadata.json
raw_memories.jsonl
consolidated_memories.json
memory_relations.jsonl
event_nodes.json
time_nodes.json
memory_graph_edges.jsonl
passage_embedding.parquet
entity_embedding.parquet
sentence_embedding.parquet
LinearRAG.graphml
```

Search is isolated by `user_id`; it does not read memories from another user
namespace.

## Implementation Notes

During `/add`, messages are split into passages, indexed by LinearRAG, and also
processed by the memory layer. The rule/spaCy memory layer extracts preference,
fact, relation, rule, event, and time signals into sidecar files. The original
passages remain the primary evidence returned by `/search`.

During `/search`, LinearRAG performs dense retrieval plus graph propagation over
passage, entity, event, and time nodes. API-level reranking then uses memory
status, sidecar memory matches, speaker hints, answer type, lexical overlap,
and temporal signals to sort the final evidence list.

## Troubleshooting

If `/health` fails:

```bash
pgrep -af 'uvicorn api_server:app'
tail -n 100 logs/api_server.log
```

If the public URL fails but local `/health` works:

```bash
pgrep -af 'cloudflared tunnel'
tail -n 100 logs/cloudflared.log
```

If `/add` or `/search` returns `401`, check that the request header token
matches `LINEARRAG_API_TOKEN` or `MEMORY_API_KEY` in the API process
environment.

If search returns an empty `data` list, confirm that:

- `/add` was called successfully for the same `user_id`.
- `request_id` was not accidentally reused for different content.
- `LINEARRAG_STORAGE_DIR` points to the intended storage directory.
- `top_k` is greater than `0`.
